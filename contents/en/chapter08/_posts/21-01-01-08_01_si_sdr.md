**Intrusive** metrics compare an enhanced signal to a **clean reference**. Scale-Invariant SDR (SI-SDR) is a workhorse in speech enhancement and source separation labs because it ignores gain mismatches that should not count as errors. This lesson builds intuition, formulas, failure modes, and how to use SI-SDR as *one* lab number — not the only ship gate.

## 60-minute teaching plan

- 0–10 min: Intrusive vs non-intrusive evaluation.
- 10–30 min: SDR → SI-SDR derivation and KaTeX formulas.
- 30–45 min: Alignment, clipping, and other failure modes.
- 45–55 min: Related metrics (PESQ/STOI at high level — when used in DNS reports).
- 55–60 min: Mini-lab outline for a batch script.

## Learning objectives

By the end of this lesson, you can:

- Explain SI-SDR meaning and scale-invariance intuition.
- State reference alignment requirements.
- Know failure modes (delay mismatch, clipping, stereo mixups).
- Use SI-SDR as a lab metric, not the sole product gate.

## Intrusive evaluation setup

You need triplets (or pairs):

- $$s$$ — clean speech reference  
- $$x = s + n$$ — noisy mixture (optional to store)  
- $$\hat{s}$$ — enhanced output  

SI-SDR needs $$s$$ and $$\hat{s}$$ **time-aligned** at the same sample rate.

## From SDR to SI-SDR

Classical SDR treats any gain error as distortion. Define the residual relative to the reference:

$$
\mathrm{SDR} = 10 \log_{10} \frac{\| s \|^2}{\| \hat{s} - s \|^2}
$$

If $$\hat{s} = \alpha s$$ for $$\alpha \neq 1$$, SDR falls even when the shape is perfect. **Scale-invariant** SDR first projects $$\hat{s}$$ onto $$s$$:

$$
s_{\mathrm{target}} = \frac{\langle \hat{s}, s \rangle}{\|s\|^2} s
$$

$$
e_{\mathrm{noise}} = \hat{s} - s_{\mathrm{target}}
$$

$$
\mathrm{SI\text{-}SDR} = 10 \log_{10} \frac{\| s_{\mathrm{target}} \|^2}{\| e_{\mathrm{noise}} \|^2}
$$

Intuition: optimally rescale the estimate, then measure residual energy.

### Worked numeric sketch

Suppose $$s = [1, 0]$$, $$\hat{s} = [2, 0]$$. Then $$s_{\mathrm{target}} = \hat{s}$$, $$e_{\mathrm{noise}} = 0$$, SI-SDR $$= +\infty$$ (perfect up to scale). Plain SDR is finite and looks "wrong" for a pure gain.

## SI-SDR vs SNR

| Metric | Compares to | Typical use |
|--------|-------------|-------------|
| Input SNR | $$s$$ vs $$n$$ in mixture | Dataset difficulty |
| Output SNR / SEGSNR | enhanced vs residual | older SE papers |
| SI-SDR | enhanced vs clean (scale-inv.) | modern SE / BSS benches |

Report **ΔSI-SDR** = output SI-SDR − input SI-SDR when mixtures are available — improvement over doing nothing.

## Reference alignment requirements

Before computing SI-SDR:

1. Same **sample rate** (resample carefully; prefer generating at model rate).
2. Same **length** — trim to min length; document which side was cut.
3. **Delay**: algorithmic latency of STFT/NS must be compensated (cross-correlation or known hop delay).
4. **Channel**: compare mono-mono; do not silently average stereo incorrectly.
5. **Gain**: SI-SDR handles global gain; it does **not** fix time-varying gain pumping artifacts completely.

## Failure modes (why a high SI-SDR can still sound bad)

1. **Uncompensated delay** — energy leaks into the residual → catastrophic SI-SDR.
2. **Clipping / resample aliasing** in the reference path.
3. **Over-suppression** that removes noise *and* consonants — may still score OK on some clips, fail listening.
4. **Non-matched reverberation** — reference is dry, estimate is wet (or vice versa).
5. **Using SI-SDR alone as ship gate** — ignores MOS, intelligibility, and realtime UX.

## Related intrusive metrics (awareness level)

DNS Challenge reports historically combine several views (exact suite evolves by year):

- **PESQ** — perceptual intrusive MOS predictor (telephony heritage; use cautiously on full-band).
- **STOI / ESTOI** — intelligibility-oriented.
- **SI-SDR / SDR** — distortion energy.

You do not need to re-derive PESQ here; know they are intrusive and reference-aligned.

## Batch evaluation outline

```text
for each clip id:
  load clean.wav, enh.wav
  assert sr match
  align delay
  si_sdr = compute_si_sdr(clean, enh)
  record row (id, noise_type, snr, si_sdr)
aggregate: mean / median / per-condition tables
```

Python labs often use well-known libraries (e.g. `numpy` reference implementation of the formula above, or established SE eval helpers). Keep the formula in your report even if you call a library.

## Common pitfalls

1. Computing SI-SDR on **mismatched delays**.
2. Comparing **enhanced** to **noisy** by mistake.
3. Reporting mean SI-SDR without SNR / noise-type breakdowns.
4. Claiming human quality from SI-SDR alone.

## Exercises

1. Implement SI-SDR in ≤15 lines of NumPy from the formulas above; test the pure-gain case.

3. On one synthetic mixture, report input SI-SDR, output SI-SDR, and ΔSI-SDR.
4. Write a one-paragraph "limits of SI-SDR" note for your capstone README.
