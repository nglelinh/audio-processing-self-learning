Web deployment of neural NS hinges on **WebAssembly** performance. **SIMD128**, threads (where permitted), memory layout, and build flags often matter as much as the model choice. This lesson teaches a practical WASM checklist for ORT-web / custom DSP kernels and how to degrade gracefully on browsers without SIMD.

## Learning objectives

You will explain why WASM SIMD changes RTF for GEMM-heavy SE, list build/feature-detect steps, relate AudioWorklet constraints to WASM instantiation, and plan a fallback path (lighter model or classical NS) when SIMD/threads are unavailable.

## 60-minute teaching plan

- **0–10 min** — Demo narrative: same ONNX, 2× RTF gap with/without SIMD.
- **10–25 min** — WASM SIMD basics; feature detection.
- **25–40 min** — ORT-web / bundler concerns; COOP/COEP for threads.
- **40–50 min** — DSP kernels (STFT, window) also benefit.
- **50–60 min** — Pitfalls, exercises.

## Core explanation

### Why SIMD helps SE

Matrix multiplies and convolutions dominate DF-class inference. SIMD loads 128-bit vectors of `f32`/`i16` and raises arithmetic throughput. Without SIMD, WASM scalar loops can miss real-time budgets on mid laptops.

### Feature detection

```js
const simd = WebAssembly.validate(new Uint8Array([
  // minimal SIMD-using module bytes — use a maintained snippet/lib
]));
```

Prefer maintained helpers from ORT-web docs or known detect libraries rather than hand-rolled bytes in production.

Ship **two builds** if needed: `model-simd.wasm` and `model-scalar.wasm`, select at runtime.

### Threads and SharedArrayBuffer

Multi-threaded ORT WASM can help—but requires **cross-origin isolation** (COOP/COEP headers) for `SharedArrayBuffer` in modern browsers. Many product sites cannot set these headers easily → **assume single-thread WASM** unless you control hosting (Ch. 07 CDN lesson). Design RTF budgets for single-thread first.

### AudioWorklet + WASM

Instantiate/compile WASM **before** the call, ideally outside the audio callback. Store exports on the processor instance. Watch memory growth: avoid per-frame allocations crossing the JS/WASM boundary; pass pointers into preallocated WASM heaps when using custom kernels.

### DSP side

Even if the net is ORT, your **STFT/OLA** in JS/WASM should also be SIMD-friendly (or done inside the graph). Profile both halves.

### Graceful degradation

```text
if (!simd || rtf_p95 > budget):
    fallback = ultra_light_model OR browser_APM_NS OR disable
```

Never silently ship crackles.

## Pitfalls

- Testing only on desktop Chrome with SIMD + isolation.
- Forgetting iOS Safari quirks / missing threads.
- Compiling with `-O0` in production artifacts.
- Huge WASM downloads without caching/CDN (06-04, 07-03).

## Exercises

1. **Detect.** Implement SIMD feature detect; log browser results in a matrix.
2. **Budget.** If scalar RTF_p95=1.1 and SIMD=0.45, what product policy do you choose?
3. **Headers.** Explain COOP/COEP in 5 bullets for your web lead.
4. **Split profile.** Propose how to time STFT vs ORT separately inside a worklet.
