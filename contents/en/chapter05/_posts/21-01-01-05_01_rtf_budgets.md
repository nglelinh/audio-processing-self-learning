**Real-time factor (RTF)** is the make-or-break metric for on-device NS: if processing 1.0 s of audio takes more than ~1.0 s of wall time on the audio thread’s budget, you will glitch. This lesson defines RTF honestly, separates **model load** from **steady-state** cost, sets browser vs native budgets, and connects RTF headroom to underrun risk (05-03).

## Learning objectives

You will define RTF and measure it with warm-up and percentile discipline, set practical budgets for browser WASM vs native threads, distinguish cold-start load from per-frame inference, and explain why average RTF lies when p95/p99 explode.

## 60-minute teaching plan

- **0–10 min** — Glitch autopsy: “RTF 0.4 average” yet crackles on battery saver.
- **10–25 min** — Definitions, formulas, measurement harness.
- **25–40 min** — Budgets: AudioWorklet quantum, native 10 ms callbacks, headroom.
- **40–50 min** — Load vs steady-state; logging for field devices.
- **50–60 min** — Pitfalls, exercises.

## Core explanation

### Definition

$$
\mathrm{RTF} = \frac{T_{\mathrm{wall}}(\text{process } D \text{ seconds of audio})}{D}.
$$

$$\mathrm{RTF}<1$$ is necessary for real-time *on that measurement setup*. It is **not** sufficient: scheduling jitter, shared cores, and callback deadlines can still underrun.

For a hop of $$H$$ seconds (e.g. $$H=0.01$$), the per-callback budget is roughly $$H$$ seconds of wall time on the audio thread (minus other work). If neural inference alone takes $$0.7H$$, you have 30% headroom for STFT, copies, and OS noise.

### Measure honestly

1. **Warm up** — run $$N$$ frames before timing (JIT, ORT arena, cache).
2. **Pin configuration** — threads=1 for WASM comparisons; document ORT intra-op threads for native.
3. **Log per-frame times** — compute p50 / p95 / p99, not only the mean.
4. **Match device class** — phone thermal throttle ≠ cold laptop.
5. **Separate load** — `session.from_model` / WASM compile time is not RTF.

```text
times = []
warm(50 frames)
for frame in test_frames:
    t0 = now()
    process(frame)
    times.append(now() - t0)
RTF_p95 = percentile(times, 95) / hop_seconds
```

### Why averages lie

A mean RTF of 0.35 with p99 RTF of 1.2 means **one frame in a hundred misses the deadline**—audible as clicks. Audio users hear tails, not averages. Always track high percentiles and max over a sliding window.

### Browser vs native budgets (rules of thumb)

| Target | Typical callback | Practical NS RTF goal | Notes |
|--------|------------------|-----------------------|-------|
| Browser AudioWorklet | 128 samples @ 48 kHz ≈ 2.67 ms render quantum (browser-dependent) | Steady inference ≪ quantum **or** gather to hop-sized blocks off the tightest path | WASM SIMD helps (Ch. 06) |
| Native VoIP thread | 10 ms common | p95 RTF < 0.5 on mid phones | Leave headroom for AEC |
| Embedded DSP | 1–4 ms | ultra-light models only | See 04-05 |

Exact AudioWorklet quanta vary; **measure** `process` interval on target browsers.

### Load vs steady-state

- **Cold start:** download weights, compile WASM, init ORT session — seconds possible; do it **before** joining a call UI-wise.
- **Steady-state:** per-hop inference + STFT/OLA.
- **First-frame spikes:** allocator / graph optimize — exclude from RTF or report separately.

### Field logging strategy

Log anonymized counters: frames_total, frames_late, rtf_p95_1s, device_model, thermal_state if available. Alert if `frames_late / frames_total > ε`. Never log raw audio from production clients without policy review.

### DeepFilterNet / ORT connection

DeepFilterNet papers report real-time feasibility on CPUs; ONNX Runtime performance docs explain graph optimizations, threading, and quantization effects. Use them as **methodology** references when writing your own harness—not as a guarantee your WASM build hits the same RTF.

## Pitfalls

- Timing including disk I/O of reading WAV every frame.
- Multi-thread ORT stealing CPU from the audio callback.
- Quoting GPU RTF for a CPU product.
- Ignoring battery saver / thermal throttling.
- Equating algorithmic latency with RTF (different concepts!).
